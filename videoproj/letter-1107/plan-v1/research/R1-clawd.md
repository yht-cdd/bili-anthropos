## 2. 外形：像素矩阵

### 2.1 官方渲染源码（2.1.319，原文摘录）【实测】

```js
// 姿势 = 眼睛 + 手臂 + 脚
jo = { default:{eyes:"open",arms:"down",feet:"both"}, "arms-up":{eyes:"open",arms:"up",feet:"both"},
       "look-left":{eyes:"left",arms:"down",feet:"both"}, "look-right":{eyes:"right",arms:"down",feet:"both"} }
Ye = { down:{r1L:" ▐",r1R:"",r2L:"▝▜",r2R:"█▀"}, up:{r1L:"▗▟",r1R:"▄",r2L:" ▜",r2R:"█▘"},
       "one-up":{r1L:" ▐",r1R:"▄",r2L:"▝▜",r2R:"█▘"} }
Xe = { open:"▛███▛█", left:"▟███▟█", right:"█▟███▟", closed:"▂███▂█"(▂为眼睑), wink:"▛███▂█" }
Je = { both:" ▝▝   ▝▝ ", left:" ▝▝      ", right:"      ▝▝ " }   // 脚
// 第1行 = r1L + 眼睛段(第2列起, 黑底) + r1R(第8列)
// 第2行 = r2L + "█████"(第2–6列) + r2R(第7列)
// 第3行 = 脚
```

旧版（2.1.100 及以前）脚是 `▘▘ ▝▝`，偏向身体中间，眼睛 `▛███▜`，**已过时**，以 2.1.319 为准。

## 4. 官方动画与表情（2.1.319）【实测】

### 4.1 基础参数
- 每拍 `za = 60 ms`；动画区高度 `bo = 3` 行；Clawd 宽 `yo = 9` 字符（= 矩阵 A 的 18 子列）
- 每个动画帧是 `{pose, offset, x, poof, shadow}`：
  - `offset`：竖直位移（单位 = 字符行 = 矩阵 A 的 **4 块**），正数往下（蹲），负数往上（在空中）
  - `x`：水平位移（单位 = 1 字符 = **2 块**）
  - `poof`：身旁的小特效字符 `dot:"·"`、`wave:"~"`（落地扬尘）
  - `shadow`：脚下阴影 `wide:"▁▁▁"` / `narrow:"▁"`
- `ts()` = 落地缓冲：`[default offset1 + "·", default offset1 + "~"]`
- 尊重系统"减少动态效果"设置（`prefersReducedMotion` 时不播放）

### 4.2 动画库（拍数 × 60ms）

| 名称 | 序列（原文意译） | 对本片的用处 |
|---|---|---|
| **jump** | 落地缓冲 → 举手 ×3 → 站 ×1 → 再来一遍 | 开心、出场 |
| **look** | 右看 ×5 → 左看 ×5 → 站 | 东张西望 |
| celebrate | jump + 蹲 ×3 | 结尾合照前 |
| **skip** | 从左侧 x=-9 起，每次 蹲→举手×2→站，x: -9→-6→-3→0，最后落地 | **从左下角跳进画面**（官方本来就是从左边蹦进来） |
| spin | 左看2 右看2 左看2 → 举手3 → 站 | |
| peekaboo | 从下面 offset 3 冒出 → 左右张望 → 举手 → 眨眼 | 从文字/框后面探头 |
| **drop** | 举手 offset -3 ×1 → -2 ×2 → -1 ×2 → 0 ×1 → 落地缓冲（扬尘 · ~）→ 站 ×3 → 眨眼 | **从高处掉下**（官方版不压扁，压扁需要自己加，见 6.3） |
| **waddle** | 从 x=-9 起，x=-6…-1 每步 2 拍，左右脚交替（feet left/right），眼睛向右 | **走路循环**：一步 2 拍（120ms），前进 1 字符（2 块） |
| peek | 从右侧探头张望再进来 | |
| wink | 眨一只眼 ×5 | |
| boop | 闭眼蹲 + 扬尘 → 左看 → 站 → 眨眼 | 被戳 / 被砸后回神 |
| **tap** | 双脚交替点地（左/右/左/右/左/右，每次 1–2 拍）→ 举手 | **打字时脚下的小动作** |
| sneeze | 闭眼举手 ×4 → 闭眼蹲 + "~" → 站 → 眨眼 | |
| **turn** | 用转身帧转一整圈（18 拍 ≈ 1.08 s） | 3D 段"回头看镜头"、在 sprite 方案里做 8 方向 |
| coin-hop | 蹲 → 举手(宽阴影) → 边转身边跳 → 举手 → 落地 | |

## 6. 设计建议（Remotion 1920×1080）【推测，基于官方数据】

### 6.1 尺寸（u = 每个正方形块的边长 px，以矩阵 A 17×10 计）
| 镜头 | u | Clawd 外框 | 占画面宽 |
|---|---|---|---|
| 远景 / 站在字幕或输入框上 | 6 | 102×60 | 5% |
| 常规陪伴（推荐默认） | **10** | 170×100 | 9% |
| 中景 / 跑进画面 | 12 | 204×120 | 11% |
| 特写（眨眼、抬头） | 24–32 | 408×240 ~ 544×320 | 21–28% |

- **u 用整数**，坐标对齐到整数像素（`Math.round`），SVG 加 `shape-rendering="crispEdges"`，避免缩放时像素边缘发糊。
- 跳到文字上时，u 可以取字号的 1/6 左右（例如 60px 字配 u=10），这样 Clawd 的身高差不多是字高的 1.7 倍。
- 视频位移量建议用"块"作单位（官方 offset 1 行 = 4u，x 1 格 = 2u），整体动作就会带官方那种一格一格的手感。

### 6.2 节奏换算
官方每拍 60 ms → **30fps 下每拍 2 帧（66.7 ms）**，60fps 下 4 帧。把官方序列照搬成"每拍 2 帧"，和终端里的节奏基本一致。

### 6.3 各动作做法
| 动作 | 做法 |
|---|---|
| **从左下角跑进来** | 官方 `waddle`：feet-left / feet-right 交替，**每步 2 拍（30fps = 4 帧），4 拍一个循环（8 帧 ≈ 0.27 s）**，每步前进 2u。"跑"可以每步改成 1 拍、前进 3–4u，并在每个循环里加 1u 上下颠簸；到位后接 `look` 或落地缓冲（扬尘 · ~） |
| **抬头看** | 官方只有左上看 / 右上看（眼睛上移 1 个子像素 = 2 块）。"正上看"【推测】：眼睛保持第 4、12 列，上移到第 0–1 行（就是 look-left/right 两帧的中间位置）。特写镜头可以只上移 1 块，过渡更细 |
| **拖鼠标点击** | 用 `one-up`（右手举起）抱住鼠标指针，点击那一下切 `arms-up` 1 拍再回来；加一圈像素点击波纹 |
| **从高处掉下 → 砸扁 → 弹回** | 前半段照官方 `drop`（举手下落，offset -3→0）；落地那一刻插入**压扁帧**（下面的 21×5 矩阵，保持 2 拍）→ 回弹拉伸帧（15×11，1 拍）→ default → 落地扬尘 → 眨眼（官方 `ui` 结尾）。**不要用 CSS scale 做连续缩放**，用离散的几张矩阵切换，像素才不会变形；需要过渡的话，最多用 scaleX/scaleY 取 1.25/0.5 这类整块比例 |
| **跳到文字上** | 官方 `jump`：落地缓冲 → 举手 ×3。空中部分用 Remotion 的 `spring()` 算抛物线，但纵坐标要取整到 u 的倍数 |
| **走到输入框打字** | 双手交替：`one-up` 和"左手举起"（one-up 的镜像，【推测】）每 2 拍切换，同时脚下放官方 `tap`；输入框里的字和手的节奏对齐（每拍出 1–2 个字）|
| **眨眼** | 官方 `closed` 保持 1 拍（30fps 下 2 帧），每 2.5–5 s 随机眨一次；偶尔连眨两下 |
| **往下滑跳出画面** | 先蹲（offset +1 = 下移 4u）→ 举手起跳 → 用 `turn` 的 back 帧背对镜头 → 快速向下滑出，最后拖 2–3 帧残影（透明度递减的同形矩阵） |
| **合照** | 结尾用 `celebrate` 或 `coin-hop`，定格在 `arms-up` 或 `wink` |

### 6.4 和 three.js 高精度 3D 场景共处：两种方案

| | A. 像素 Sprite（平面贴图 / billboard） | B. 体素 Voxel 模型 |
|---|---|---|
| 做法 | 矩阵画成 CanvasTexture，`NearestFilter`、关掉 mipmap，贴在永远朝向相机的平面上；可以按相机方位角从官方 13 个转身帧里挑一张，做成"8 方向精灵" | 同一份矩阵挤出厚度，用 `InstancedMesh` 的小方块拼出来；手臂、眼睛、4 只脚拆成独立部件，方便按官方姿势切换 |
| 一致性 | 和 2D 段**完全一样**，动画数据直接复用 | 正面看和 2D 一致，侧面需要自己定义厚度（官方 edge 帧宽 5 块，可以作依据：**厚度约 5–6u**） |
| 光照融合 | 差：没有体积，夕阳侧光、投影都要另外假造；镜头绕到侧面时露出"纸片" | 好：能吃到夕阳的方向光、阴影、环境光遮蔽，和城市融在一起 |
| 和鲸鱼同框 | 鲸鱼如果是 3D 的，两者体积感不一样，会出戏 | 体素鲸鱼 + 体素 Clawd，风格统一 |
| 工作量 | 小 | 中（建模可以用代码从矩阵生成，大约 200 个方块；动画只是切换部件可见性和位移） |
| 性能 | 极低 | 低（200–400 个 instance，毫无压力） |
| 风险 | 3D 运镜越多越露馅 | 方块边缘在暖光下容易糊成一片 → 加 0.02u 倒角或描边，暗部用 #B55F43 |

**推荐 B（体素）作为 3D 城市段的主方案**，原因：要和鲸鱼漫游、合照，镜头一定会绕；另外社区已有 three.js 体素 Clawd 的先例，观众接受度高。细节：
- 体素 1 块 = 矩阵 1 块，深度 6 块，眼睛做成凹进 0.5 块的黑色方块（侧面不会露出白眼）
- 材质：`MeshStandardMaterial({color:'#D77757', roughness:0.85, emissive:'#D77757', emissiveIntensity:0.12})`，必要时用 toon/flat 着色让它和写实城市稍稍区隔
- **转场亮点**：2D 段结束时，SVG 像素块一个个"浮起"变成 3D 方块（同一套坐标），自然进入 3D 城市
- 远景小于 80px 时可以退回 sprite（LOD），省事又不穿帮

### 6.5 和高精度场景协调的小技巧【推测】
- 城市整体做一层轻微的色调分离 / 低饱和，让 Clawd 的纯橙成为视觉焦点
- 给 Clawd 加一个紧贴脚下的小方形阴影（呼应官方的 `▁▁▁` 阴影字符）
- 镜头景深：Clawd 保持锐利，背景虚化，像素的硬边反而成了风格

### 6.6 Remotion 组件骨架（示意）
```tsx
import poses from './R1-clawd-poses.json'; // 键: default / arms-up / look-left / ... / facing:back
const C = {1:'#D77757', 2:'#000000'} as const;
export const Clawd: React.FC<{pose?: keyof typeof poses; u?: number}> = ({pose='default', u=10}) => {
  const g = poses[pose] as string[];          // 每行是 '00111...' 字符串, 17 列 x 10 行
  return (
    <svg width={17*u} height={g.length*u} shapeRendering="crispEdges">
      {g.flatMap((row, y) => [...row].map((v, x) => v !== '0' &&
        <rect key={`${x}-${y}`} x={x*u} y={y*u} width={u} height={u} fill={C[+v as 1|2]} />))}
    </svg>
  );
};
// 动画: const beat = Math.floor(frame / 2); pose = seq[beat % seq.length]  (30fps, 官方 60ms/拍)
```
