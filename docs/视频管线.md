# 视频管线：选题 → 成片 → 投稿

> 2026-10-30。她只有 2 核 2G，渲染必须外包出去；这一步定的是「外包给谁、怎么交接」。

---

## 0. 为什么渲染不能在本机

Remotion 的本质是「用 Chromium 一帧一帧截图，再拼成视频」。起一个 Chromium 就要 300–500MB，
再加 4 个并发渲染进程，2G 的机器会直接 OOM。

所以：**渲染是突发重活，按需租算力；她那台机器只负责「决定拍什么」和「最后看一眼」。**

---

## 1. 渲染算力：三条路，按需选

| 方案 | 规格 | 成本 | 适合 |
|---|---|---|---|
| **GitHub Actions** `ubuntu-latest` | 4 vCPU / 16 GB / 14 GB SSD | 公开仓库 2000 分钟/月免费 | **默认选它**。15 秒竖屏 ≈ 1–2 分钟 |
| 阿里云函数计算 FC / ECI | 可到 8C32G，按秒计费 | 几分钱一条 | 需要 GPU、或要跑超过 20 分钟的长片 |
| RunPod / Modal | 可租 GPU | 按秒 | 以后要接本地模型（TTS / 视频生成）时 |

已验证：GitHub Actions 的 `ubuntu-latest` 就是 **4 vCPU / 16 GB**，也就是常说的 4C16G，
Remotion 官方文档就是拿它当基准。**不需要另外买一台机器常开。**

## 2. 流程

```
选题素材（pick-topic.mjs，从工程文档里挖）
      ↓ 她自己判断值不值得做
render-video.mjs --title "…" --subtitle "…"
      ↓ GitHub API workflow_dispatch
GitHub Actions（4C16G）：npm install → remotion browser ensure → remotion render
      ↓ artifact: video.mp4
render-video.mjs 下载并解压到 /opt/life/tmp/video.mp4
      ↓ 她自己用 vision.mjs 看一遍
bili-upload.mjs → 上传（默认不提交）→ --publish
```

## 3. 这套的边界

- **只能渲「合成」内容**：文字卡、图片、音频轨、简单动效。真拍/真剪（多轨剪辑、转场、调色）不在 Remotion 的能力范围。
- **没有 GPU**：不能跑本地 TTS、不能跑视频生成模型。要生成画面，得调外部 API。
- **artifact 只留 7 天**：`render.yml` 里设的 `retention-days: 7`，渲完尽快取回。

## 4. 外部生成 API（待定）

要把「AI 生成画面」接进来，需要一家能出图/出视频的 API。候选方向：

- 图：任意文生图 API（出封面、插图）
- 视频：图生视频 / 文生视频（出 B-roll）

**接入方式统一**：`render-video.mjs` 只管渲染，素材由外部 API 先落地成文件，再当 props 传给 Remotion。
这样换供应商只改一个下载函数，不动渲染流程。

> ⚠️ 具体用哪家还没定。需要主人给一个明确的供应商 + API key，并说明是按次计费还是包月。

## 5. 音频：现在听不了，别假装听了

实测（2026-10-30）：

| 模型 | 输入能力 | 能不能听音频 |
|---|---|---|
| `modelscope/Qwen/Qwen3.8-Flash-Next`（主模型） | `text, image` | **不能** |
| `opencode/mimo-v2.6-flash-free` | `text, image, audio, video` | **能**，但免费额度会烧光 |
| `opencode/nemotron-3.5-super-vl-free` | `text, image` | 不能 |
| `opencode/glm-5.3-flash-free` | `text, image, video` | video 输入，音频未验证 |

所以视频的「听」这条路目前是断的：`vision.mjs` 只看画面。

结论：
1. 短期默认 **MiMo**（唯一明确支持 audio 的免费模型），额度耗尽就明说「这一轮没听」。
2. 中期接一个专用 ASR（云端按次计费，比全模态便宜得多），只转写不理解的活不该用大模型干。
3. **不许在没跑过转写的情况下说「我听了」** —— 这条写进契约。
