# 语音：让她开口，也让她听见

> **本仓库不指定供应商。** 你需要自己配一个 TTS（以及可选的 ASR）服务。
> 我们只提供适配层，换服务商不改代码。

---

## 1. 为什么视频必须先解决这个

一条片子有三个要素：画面、字幕、**声音**。

画面能生成（[素材生成](素材生成接入.md)），字幕能渲（Remotion），
但没有声音的片子，观众三秒就划走。之前整条链路就卡在这里 —— 能出片，但是哑的。

另外，同一个服务往往**同时给 TTS 和 ASR**：
- TTS → 给自己的视频配音
- ASR → 听懂别人的视频（这比"看画面"更接近"看懂"）

## 2. 怎么接

```bash
cp config/voice-api.example.json config/voice-api.json
# 填 baseUrl / 模型名；key 放 secrets/voice_api_key.txt（600）

node scripts/voice.mjs voices                      # 列可用音色
node scripts/voice.mjs say "要说的话" --out a.mp3   # 合成
node scripts/voice.mjs say --file 口播稿.txt --out a.mp3
node scripts/voice.mjs hear a.mp3                  # 识别
node scripts/voice.mjs plan --file plan.json --out-dir tmp/ep01   # 按时间轴配音
node scripts/voice.mjs usage                       # 今天用了多少次
```

### 按时间轴配音（推荐）

别的做法都是"先合成，再看多长"，视频只能追着音频改，必然错位。
这里反过来：**先定时间轴，再让每段填满窗口**。

```json
{
  "segments": [
    { "from": "00:00:00", "to": "00:00:04", "text": "这是第一段，四秒。" },
    { "from": "00:00:04", "to": "00:00:10", "text": "第二段六秒，把话讲完整。" }
  ]
}
```

```bash
node scripts/voice.mjs plan --file plan.json --out-dir tmp/ep01
# → seg-01.mp3 … voice.mp3 + timeline.json
```

- 短了 → 补静音到正好
- 长了 → 加速（`atempo`），**上限 1.25x**，超了就报错让你删稿，不偷偷变声
- 输出 `timeline.json`：每段的 from/to/实际时长，Remotion 直接拿它切场景

实测：计划 13 秒，成片 13.04 秒，**累积漂移 35 毫秒**。

然后：

```bash
node scripts/render-video.mjs --title "标题" --timeline tmp/ep01/timeline.json --audio tmp/ep01/voice.mp3
```

渲染机按时间轴切画面，返回后自动把音轨合进去。

## 3. 两种接口形态

各家做法不统一，脚本认这两种（配置里 `style` 切换）：

| style | 长什么样 | 适合 |
|---|---|---|
| `chat`（默认） | 挂在 `chat/completions` 上：TTS 把文本放进 **assistant** 角色，服务把这条"读出来"；ASR 只收音频、**不能带文本** | 把语音做成对话接口的服务 |
| `endpoint` | 标准 OpenAI 形态：`/v1/audio/speech`（返回二进制）、`/v1/audio/transcriptions`（multipart） | 兼容 OpenAI 的服务 |

适配细节：

- TTS 返回可能是 **base64**（在 `choices[0].message.audio.data`）也可能是**二进制**，脚本两种都处理
- 音频统一转成 **mp3 128k**（靠 ffmpeg），方便直接塞进 Remotion
- 长文本按句号切块逐段合成，再用 ffmpeg concat 拼起来 —— 一次几万字会被服务端截断

## 4. 实测记录（2026-10-30）

在这台 2C2G 的机器上：

| 动作 | 结果 |
|---|---|
| 合成 30 字 | 5.2 秒音频，83KB mp3，一次调用 |
| 识别同一段 | **0.78 秒**，文字基本一致（"她"听成"他"，同音误差） |
| 可用音色 | 9 个（含中文名与英文名） |

结论：**CPU 机器完全够用** —— 语音是走服务端的，不吃本地算力。
这也是为什么不需要在这台机器上跑 GPT-SoVITS / CosyVoice 那类本地模型：
它们要 GPU 或至少 4G 内存，CPU 推理一句要几十秒。

## 5. 免费方案怎么选（2026-10 现状）

| 路线 | 成本 | 代价 |
|---|---|---|
| 云端 TTS 的免费额度 | 免费 | 要注册、有月度字数上限，够个人用 |
| 自建 GPT-SoVITS / CosyVoice / Fish | 免费 | **要算力**。2C2G 跑不动；租 GPU 就不是免费了 |
| 浏览器朗读接口（非官方） | 免费 | 无 SLA，随时可能变，别用在生产 |

判断标准很简单：**你的机器有没有 GPU**。没有就走云端免费额度，别自建。

## 6. 音效：不用任何 API，算出来就行

**先做音效，再考虑人声。** 音效是 ffmpeg 合成的，免费、不排队、时长精确到毫秒；
人声必须调外部服务，会排队、会失败、会超时长。别让片子因为"配音没配好"发不出去。

```bash
node scripts/sfx.mjs list                       # 有哪些
node scripts/sfx.mjs make --cue whoosh --seconds 0.9 --out a.mp3
node scripts/sfx.mjs mix --plan audio.json --out audio.mp3
```

内置 8 种：`tick`（轻点）、`ding`（叮）、`boom`（低频重音）、`buzz`（警告）、
`whoosh`（转场）、`riser`（上升）、`pad`（氛围垫）、`typing`（打字）。

`audio.json`：

```json
{
  "total": 13,
  "bed":  { "cue": "pad", "gain": 0.18 },
  "cues": [
    { "at": 0,    "cue": "ding",   "gain": 0.7 },
    { "at": 3.8,  "cue": "whoosh", "seconds": 0.9, "gain": 0.6 },
    { "at": 10,   "cue": "boom",   "gain": 0.8 }
  ],
  "voice": "tmp/ep01/voice.mp3"
}
```

- `bed` 铺满整条，`cues` 按 `at` 摆放，`voice` 有就混进去、没有就纯音效
- 结尾统一过 `alimiter` + `loudnorm`（-16 LUFS），不会爆音也不会忽大忽小
- 实测：计划 13 秒 → 实际 13.04 秒，峰值 -1.9 dB

## 7. 还没做

- **音色克隆**：多数服务有 `voiceclone` 之类的模型，脚本没接
- **字幕对齐**：现在只有音频，没有逐句时间轴。要精准字幕得让 TTS 返回时间戳，或另接一个强制对齐
- **背景音乐 / 混音**：Remotion 能放音轨，但"人声 + BGM 自动压低"没做
