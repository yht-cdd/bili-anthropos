# 生成素材：Agnes 出图 / 出片

> 2026-10-30 实测。域名是 **`api.agnes-ai.cn`**，不是 `.ai`。

---

## 1. 两个域名不是一回事

| 域名 | 状态 | 说明 |
|---|---|---|
| `apihub.agnes-ai.com` | 老网关 | 手册里写的那个。key 能用，但**间歇性 401**（同一把 key 一分钟前 200、一分钟后 401），不能当生产用 |
| `api.agnes-ai.cn` | **现在用这个** | 平台 `platform.agnes-ai.cn` 签发的 key，稳定 |

`.cn` 的接口 schema 和 `.com` 的老文档**不一样**，照抄老文档会一直 400。

## 2. 可用模型（`GET /v1/models`）

```
agnes-2.5-flash          agnes-2.5-pro           agnes-2.5-pro-alpha
agnes-2.5-pro-beta       agnes-3.0-flash         agnes-image-2.1-flash
agnes-image-2.5-flash    agnes-video-2.5         agnes-video-2.5-flash
```

## 3. 出图（已验证）

```http
POST /v1/images/generations
Authorization: Bearer <key>

{"model":"agnes-image-2.5-flash","prompt":"…","size":"1024x1024",
 "extra_body":{"response_format":"url"}}
```

返回 `{"data":[{"url":"https://cos-platform-outputs.agnes-ai.cn/..."}],"task_id":"…"}`。

实测：512×512 从服务器发起，**7.8 秒**返回，产物 538KB，无平台水印。

`b64_json` 字段存在但为空 —— 要拿二进制就下载 `url`。

## 4. 出片（结构对，但队列常满）

```http
POST /v1/videos
{"model":"agnes-video-2.5-flash","prompt":"…","mode":"text"}
```

`.cn` 的字段规则（都被 400 逐个试出来的）：

| 字段 | 结论 |
|---|---|
| `num_frames` | **禁止字段**（老文档这么写，新接口直接拒） |
| `duration` | **禁止字段** |
| `mode` | **必填**。`text` = 文生视频；`keyframe` = 首尾帧（要配 `first_frame` / `last_frame`，data URI） |
| `prompt` | 必填 |

**现在的实际状态**：连试 6 次都是 `503 video_queue_full`（视频队列已满）。
说明请求结构是对的，但平台侧排不上队 —— 这不是我们能修的。

所以：
- `gen-media.mjs video` 已经写好，遇到 503 会明确告诉你「队列满，不是我们的错」并退出码 4
- **任务查询接口还没验证过**（没拿到过 task id）：脚本里依次试
  `/v1/videos/{id}`、`/agnesapi?video_id={id}`、`/v1/videos/query?id={id}`，
  哪个先回 200 用哪个。等队列空出来跑通一次，再回来把这段收敛成一条。

## 5. 花钱的闸门

生成是**付费**动作，所以 `gen-media.mjs` 带了三道：

1. 每日上限（默认 10 次，`AGNES_DAILY_MAX` 可调），到顶拒绝，`--force` 才能突破
2. 每次生成写 `bili/data/gen_usage.jsonl`（模型、提示词、字节数、耗时）
3. `gen-media.mjs usage` 一眼看今天生成了什么

## 6. 还没接的

- **图生图 / 参考图**：`agnes-image-2.5-flash` 是否支持 image 入参，没测
- **视频查询接口**：见上，等一次成功的任务
- **TTS（配音）**：Agnes 没有语音合成，Remotion 那条线现在是无声的
- **EXA 搜索**：本机没有任何 EXA 技能或连接器，`api.exa.ai` 需要单独的 key
