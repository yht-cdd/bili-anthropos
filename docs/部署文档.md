# Anthropos 云端部署文档

> 目标：让 AI 角色 Anthropos 在一台云服务器上 7×24 常驻运行，拥有连续记忆与自主行动能力。
> 创建：2026-10-30 · 最后更新：2026-10-30

---

## 0. 设计原则

| 原则 | 含义 |
|---|---|
| **身体在云上，手在桌面** | 云服务器 7×24 活着；本地 Windows 只在扫码登录/过验证时出手 |
| **进程会结束，但她活在磁盘上** | 每次 `opencode run` 是独立 session，连续性靠 `life/` 目录里的文件 |
| **不允许自欺** | 她可以"今天不想动"，这是生命感，不是 bug |
| **只读优先** | B 站只读，不开放评论/私信自动化 |

## 4. 踩坑记录

### 4.1 密码末尾的句号

用户报的密码是 `<YOUR_SSH_PASSWORD>`，实测**失败**。正确值是 `<YOUR_SSH_PASSWORD>`（末尾无点）。那个点是句号标点。

### 4.2 `opencode-ai` 是 V1，`@opencode/cli` 是 V2

这是最容易踩的坑：

| 包名 | latest | 是什么 |
|---|---|---|
| `opencode-ai` | **1.19.5** | **V1**（遗留包名，永远停在 1.x） |
| `@opencode/cli` | **2.2.2** | **V2**（当前版本） |

```bash
npm i -g opencode-ai      # ❌ 装 V1
npm i -g @opencode/cli    # ✅ 装 V2
```

V2 的 `@opencode/cli` 依赖平台二进制包 `@opencode/cli-linux-x64`，且带 `postinstall` 脚本。

### 4.3 npm 11 默认拦截 postinstall

```
npm warn install-scripts 1 package has install scripts not yet covered by allowScripts:
npm warn install-scripts   opencode-ai@1.19.5 (postinstall: node ./postinstall.mjs)
```

解决：

```bash
npm config set allow-scripts=opencode-ai --location=user
npm config set allow-scripts=@opencode/cli --location=user
npm i -g <包名> --force
```

### 4.4 服务器上的 jq 解析 index.json 失败

`curl | jq` 拿 npmmirror 的 `index.json` 会报 `Invalid numeric literal`。改用本机解析 + 固定版本号。

### 4.5 PowerShell 执行远程脚本的转义地狱

**不要**用 `ssh "内联长命令"`。正确做法：

```powershell
# 1. 本地写 .sh 文件
# 2. Base64 编码
$b64 = [Convert]::ToBase64String([System.Text.Encoding]::UTF8.GetBytes($content))
# 3. 远程解码执行
ssh root@IP "echo '$b64' | base64 -d > /tmp/_run.sh && bash /tmp/_run.sh; rm -f /tmp/_run.sh"
```

脚本已封装在 `C:\Users\正星gj\AppData\Local\Temp\opencode\remote\run_remote.ps1`。

### 4.6 SSH 密码自动化

Windows 无 `sshpass`。用 `SSH_ASKPASS`：

```powershell
# askpass.bat 内容：@echo off \r\n echo <YOUR_SSH_PASSWORD>
$env:SSH_ASKPASS = "路径\askpass.bat"
$env:SSH_ASKPASS_REQUIRE = "force"
$env:DISPLAY = "localhost:0"
ssh -o PreferredAuthentications=password -o PubkeyAuthentication=no root@IP "..."
```

### 5.6 压力分（六力）

```js
pressure = 0.25*attention_debt     // 未读内容数 / 20
         + 0.20*info_decay         // 距上次反思小时数 / 168
         + 0.20*relation_cooling   // 距上次对话小时数 / 72
         + 0.15*unanswered         // QUESTIONS.md 超 3 天的条数 / 5
         + 0.10*fatigue            // 今日行动次数 / 6
         + 0.10*cost               // 今日花费 / 日预算
```

| 分数 | 行为 |
|---|---|
| < 0.2 | 写一行"今天没什么想做的"，睡回去 |
| 0.2–0.6 | 做一件事 |
| > 0.6 | 忙一天 |

### 8.2 架构：三级轮询

```
systemd: bili-daemon.service
    │
    ├─ L0 每 30s   GET /x/msgfeed/unread       45ms  200字节
    │   └─ 全为 0 → 直接下一拍，什么都不做
    │
    ├─ L1 计数 > 0 才执行
    │   ├─ at    > 0 → GET /x/msgfeed/at
    │   ├─ reply > 0 → GET /x/msgfeed/reply
    │   └─ chat  > 0 → GET get_sessions → fetch_session_msgs
    │
    └─ L2 每 8 拍（约 6 分钟）
        ├─ GET member/x/web/archives
        ├─ 每个已发布稿件 GET /x/v2/reply/count   ← 165ms，只返回总数
        └─ count 增长才拉 /x/v2/reply/main?mode=2
              │
              ▼
        SQLite /opt/life/bili/data/bili.db
        （events 表，主键去重，幂等）
              │
              ▼
        bili-send.mjs 四道闸 → 发送
```

### 10.4 踩坑

| # | 坑 | 症状 | 修法 |
|---|---|---|---|
| 1 | `ExecStart=/usr/bin/node` | `status=203/EXEC`，服务反复重启 | 改成 `/usr/local/bin/node` |
| 2 | `POST /prompt` 只给 `location` + `agent` | 返回 200、消息 `delivery: "steer"`，但 session 永远只有 `busy` 没有 `idle` | **必须同时给 `model`** |
| 3 | 以为 `GET /session` 的 200 是 API | 拿到的是 SPA 的 HTML | 真正的 API 在 `/api/*` 下 |
| 4 | 用 Bearer / x-api-key 鉴权 | 全部 401 | 用 **Basic auth，用户名 `opencode`** |
| 5 | `msg_key` 当去重键 | 19 位数字超 JS 安全整数，精度丢失导致误判 | 用 `timestamp\|sender_uid\|sha1(content)` |
| 6 | `session_ts` 单位当毫秒 | 时间比较全部失效 | 它是**微秒** |
| 7 | 首次启动就把历史消息全处理 | 会把几个月前的私信当成新任务 | 建基线时全部标记为已见 |
