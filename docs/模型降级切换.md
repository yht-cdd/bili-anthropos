# 模型降级切换

> 一份开关，管住三套互相不知道对方死活的配置。

## 为什么需要它

2026-10-31 早上发现：魔搭账户返回 `insufficient balance`，四个模型全挂。

但她的模型配置是**三套独立**的：

| 用途 | 配置在哪 | 出问题时的表现 |
|---|---|---|
| 主模型（大脑） | `/root/.config/opencode/opencode.json` + bridge 的 `OC_MODEL` | 她回不出话，看起来像「不想理人」 |
| 子代理 | `config/agent-models.json` 的 ladder | 派活全部失败，报「免费模型都用完了」 |
| 看视频 / 看图 | `scripts/vision.mjs` 的 `CHAIN` | 视觉调用报错，她只能干说「我看不了」 |

三套各自挂在同一个魔搭 key 上，一处额度用完，三处同时哑掉，
**但没有一处会告诉另外两处**。这就是那天她沉默的直接原因。

## 怎么用

```bash
node scripts/model-mode.mjs status      # 现在什么模式
node scripts/model-mode.mjs set auto    # 切回魔搭优先（0 点日切自动做）
node scripts/model-mode.mjs set amd     # 降级到 AMD（额度报错时自动做）
```

`set` 一次改四个地方：

1. `config/model-mode.json` —— 模式状态（`vision.mjs` 读它决定链顺序）
2. `/root/.config/opencode/opencode.json` 的默认 `model`
3. `/root/.opencode.env` 的 `OC_PROVIDER_ID` / `OC_MODEL_ID`
4. `config/agent-models.json` 的 ladder 顺序

不重启任何服务。`vision.mjs` 每次运行都重读状态文件，
`spawn-task.mjs` 每次运行都重读 ladder，所以改完立刻就生效。

## 自动切换的两端

| 触发 | 动作 | 代码位置 |
|---|---|---|
| 某一轮失败，`describeFailure` 判成 `quota` | `switchModelMode("amd")` + 改绑当前会话 + 重试 | `bili-bridge.mjs` → `runTask` |
| 00:00 固定日切 | `switchModelMode("auto")` + 改绑当前会话 | `bili-bridge.mjs` → 到点分支 |

判定 `quota` 的依据（`describeFailure`）：

```
status === 429 或 消息里出现 quota / insufficient / balance / rate-limit / 额度 / 余额 / 用量
```

## 两种模式各自的配置

| | `auto`（常态） | `amd`（降级） |
|---|---|---|
| 主模型 | `modelscope/Qwen/Qwen3.8-Flash-Next` · variant `high` | `amd/Qwen3.8-Flash-Next` · variant `medium` |
| 子代理阶梯首位 | 魔搭 | AMD |
| 视觉链首位 | 魔搭 | AMD |

> `variant` 不一样的原因：AMD 的 Qwen3.8-Flash-Next **不接受 `high`**，
> 只接受 `none` / `low` / `medium` / `xhigh`。写错会被网关拒掉。

## 实测（2026-10-31）

```
① 切 auto
   opencode.json : brocod/deepseek-v4.1 → modelscope/Qwen/Qwen3.8-Flash-Next
   阶梯首位      : modelscope/Qwen/Qwen3.8-Flash-Next

② 模拟一条任务
   ↻ 这一轮失败了（quota: 模型额度用完了（429 / 余额不足）），按约定重试一次
   🔀 模型模式 → amd：amd/Qwen3.8-Flash-Next
   🔧 已把会话模型改绑到 amd/Qwen3.8-Flash-Next
   ✅ 重试成功 → 「在线」

③ 最终模式：amd
```

速度对比（同一个会话、同一个问题）：

| 模型 | 结果 | 耗时 |
|---|---|---|
| `brocod/deepseek-v4.1` | succeeded | 3.0s |
| `amd/Qwen3.8-Flash-Next` | succeeded | 3.0s |

第一次降级那次重试花了 205 秒，是 AMD 的冷启动，不是常态。

## 踩过的坑

1. **`variant` 不能跨厂商照抄**。`high` 在 DeepSeek 系和魔搭能用，在 AMD 的 Qwen3.8 上不合法。
2. **降级不等于换会话**。只 `rebindModel` 改绑模型，会话记忆不动 —— 换会话会丢记忆。
3. **已经在 amd 模式还报额度错，就不要再切了**，否则会来回抖动。代码里用
   `readModelMode() !== "amd"` 挡了一下。
4. **opencode.json 的默认模型要重启 opencode 才对 Web UI 生效**，但 bridge 创建会话时
   显式传 `model`，所以对话不受影响。
