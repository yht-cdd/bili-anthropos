# 模型降级切换

> 一份开关，管住三套互相不知道对方死活的配置。

## 为什么需要它

2026-10-31 早上发现：魔搭账户返回 `insufficient balance`，四个模型全挂。

但她的模型配置是**三套独立**的：

| 用途 | 配置在哪 | 出问题时的表现 |
|---|---|---|
| 主模型（大脑） | `/root/.config/opencode/opencode.json` + bridge 的 `OC_MODEL` | 她回不出话，看起来像「不想理人」 |
| 子代理 | `config/agent-models.json` 的 ladder | 派活全部失败 |
| 看视频 / 看图 | `scripts/vision.mjs` 的 `CHAIN` | 视觉调用报错 |

三套各自挂在同一个 key 上，一处额度用完，三处同时哑掉，
**但没有一处会告诉另外两处**。这就是那天她沉默的直接原因。

## 怎么用

```bash
node scripts/model-mode.mjs status    # 现在什么模式
node scripts/model-mode.mjs set auto  # 切回魔搭优先（0 点日切自动做）
node scripts/model-mode.mjs set amd   # 固定 AMD Qwen3.8（额度报错时自动做）
```

`set` 一次改**五**个地方：

1. `config/model-mode.json` —— 模式状态（`vision.mjs` 读它决定链顺序）
2. `/root/.config/opencode/opencode.json` 的默认 `model`
3. `/root/.opencode.env` 的 `OC_PROVIDER_ID` / `OC_MODEL_ID`
4. `config/agent-models.json` 的 ladder 顺序（没有这个 provider 会自动补一条）
5. **把已有会话改绑过去**（调 opencode API）

第 5 条最容易漏：`opencode.json` 的 `model` 只影响**新建**会话。
已有会话会一直绑着创建时的模型，所以会出现「默认模型已经换了，
但 Web UI 里那个会话还指着死模型，发一句挂一句」。

## 两种模式

| | `auto`（常态） | `amd`（降级） |
|---|---|---|
| 主模型 | `modelscope/Qwen/Qwen3.8-Flash-Next` · `high` | `amd/Qwen3.8-Flash-Next` · `medium` |
| 上下文 | 1M | 262k |
| 视频 | **直传** mp4（真视频理解） | **抽帧 + ASR**（见下） |
| 子代理阶梯首位 | 魔搭 | AMD |

## 视频链路：AMD 不吃视频怎么办

AMD 的 Qwen3.8-Flash-Next 只接受 `image_url`，传 `video_url` 会被 schema 直接拒掉：

```
{"code":"invalid_literal","expected":"image_url","path":["messages",0,"content",0,"type"]}
```

所以 `vision.mjs video` 会先看链首的模型能不能吃视频（`VIDEO_CAPABLE` 只登记了魔搭的
Qwen3.8-Flash-Next），不能就自动改走 **抽帧 + ASR**：

```
① ffmpeg 抽帧 → 拼成一张九宫格（按时间从左到右、从上到下）
② ffmpeg 抽音轨 → voice.mjs hear（小米 MiMo ASR）转文字
③ 帧图 + 转写一起交给模型：「画面讲了什么，声音说了什么，对不上就直说」
```

实测（2026-10-31，`anthropos-intro-with-audio.mp4`）：

> 画面在讲一个自称 Anthropos 的 AI 在 2026 年醒来、宣告自己的存在方式……
> 音轨转写只有一个字："嗯。" 没有旁白。
> **对不上**：画面每一帧都是成段中文，但音频里完全没有念出来 —— 那些是做在画面里的字幕墙，不是口播。

这比直传还多了一层判断：**音画对不对得上**。

## 自动切换的两端

| 触发 | 动作 | 代码位置 |
|---|---|---|
| 某轮失败，`describeFailure` 判成 `quota` | 压缩会话 → 切 `amd` → 改绑 → 重试 | `bili-bridge.mjs` → `runTask` |
| 00:00 固定日切 | 切回 `auto` + 改绑 | `bili-bridge.mjs` → 到点分支 |
| bridge 启动 | 把会话改绑到当前模式的模型 | `bili-bridge.mjs` → 启动自检 |

### 切 AMD 之前必须先压缩

AMD 只有 262k 窗口，她的会话可能 329k。不压就切，请求会被后端直接拒：

```
The input (329407 tokens) is longer than the model's context
```

表现是「3 秒就结束、outcome=failed、正文还是上一轮的残留」，特别像「她不想说话」。
所以 `runTask` 里先跑 `compactForAmd()`：超 88% 就调 `/compact`，等 12 秒再看一次。

## 实测（2026-10-31）

```
① 切 amd
   会话改绑：10 个改绑到 amd/Qwen3.8-Flash-Next
   上下文上限：262144 → 压缩线 235929（90%）· 硬线 249036（95%）

② 视频（AMD 模式）
   → 首选模型（amd）不吃视频，改走「抽帧 + ASR」
   → 抽帧 9 张（3×3 网格）
   → ASR 3 字：「嗯。」
   输出：画面讲什么、声音是什么、音画对不上 —— 全对

③ 主会话
   当前上下文: 54516 tokens（opencode 自动压缩过）
   outcome: succeeded  3.0s
```

## 踩过的坑

1. **`variant` 不能跨厂商照抄**。`high` 在 DeepSeek 系能用，在 AMD 的 Qwen3.8 上不合法
   （只接受 `none` / `low` / `medium` / `xhigh`）。
2. **改默认模型 ≠ 改会话绑定**。这是当天「没自动切换」的直接原因。
3. **Web UI 手动对话不经过 bridge**，自动降级管不到；
   只有把会话本身改绑过去，手动聊天才会跟着好。
4. **降级不等于换会话**。只 `rebindModel`，记忆不动。
5. **已经在 amd 还报额度错就不要再切**，否则来回抖动。
6. **opencode 当前版本不认 `attachment` / `reasoning`**（`omitted unsupported legacy setting`），
   输入类型要用 `modalities` 表达。
7. **直接给会话发 prompt 会绕过 bridge 的语义包装**。测试时发「只回两个字：在的」，
   她理解成「去发一条『在的』」，真的用 bili-dm 发了 —— 测试要写清楚「这是系统测试，不要对外发」。
